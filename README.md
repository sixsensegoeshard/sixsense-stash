# 301secrets Tracker

Telegram-бот для учёта активности в группе: статистика, плейсменты, прогресс ролей и отчёты. Основной интерфейс — кнопки в личном чате с ботом.

## Чистый интерфейс

Компактные карточки, иконки разделов, прямой текст без курсива в именах, не более двух кнопок в строке. Статистика показывает ненулевые категории и серию без лишних отступов; сравнение появляется только при ненулевой базе и изменении активности. Главная администратора показывает активность группы за текущий месяц. В профиле оставлены основные действия; заметки, последние сообщения и история правок открываются через **Ещё**. Возврат из профиля сохраняет страницу, поиск и сортировку участников. Добавление записи показывает текущий шаг, сохранение требует подтверждения.

Используется стандартное оформление Telegram с визуальными акцентами для быстрого чтения. Цвета, шрифты и кнопки следуют теме приложения пользователя.

Выбранный период и основные действия выделены синим, сохранение — зелёным, удаление и его подтверждение — красным. Ключевые цифры показаны отдельным блоком, длинные тексты истории правок сворачиваются. Используются нативные стили Telegram; конкретные оттенки зависят от клиента и темы.

Для проверки текстов и кнопок без Telegram и рабочей базы:

```bash
.venv/bin/python tools/preview_ui.py /tmp/tracker-ui/index.html
```

Открой полученный HTML: он показывает реальные карточки на синтетических данных в светлой и тёмной темах при ширине 320 px. Это макет для проверки компоновки, не отдельный веб-интерфейс бота.

## Интерфейс

Длинные действия не обрезаются ради двух колонок: при необходимости каждая кнопка получает отдельную строку. Выбранный период выделяется цветом. Рейтинг подписывает значения: действия, лупы, дни или баллы. Категория видна в заголовке, в том числе при отсутствии результатов.

Возврат из записи сохраняет страницу, из прогресса роли — список и фильтр ролей, из профиля — выбранный период активности. Отмена повторного поиска возвращает прежние результаты. Старая кнопка сохранения не заменяет экран успешной операции.

Повторный запуск из той же папки блокируется до подключения к Telegram. Файл `.trackerbot.lock` остаётся на диске намеренно: блокировкой владеет процесс, а не сам файл; вручную удалять его не нужно. Проверено на macOS и Linux; код для Windows включён, но на Windows отдельно не проверялся.

Открой бота и отправь `/start` или `/menu`:

- **Активность** — сообщения и вложения за 7 дней, 30 дней, месяц или всё время; сравнение с предыдущим сопоставимым периодом.
- **Профиль** — плейсменты, прогресс к роли и общая сводка. История по месяцам доступна сразу, включая текущий месяц.
- **Участники** (администратор) — сначала недавно активные в группе, есть сортировка по имени. Поиск по части имени / username, точному `@username` или ID. Несколько совпадений показываются кнопками; можно переслать сообщение с открытым автором.
- **Рейтинг** (администратор) — выбор периода и категории кнопками; рейтинг «По вкладу» учитывает разные виды активности и показывает формулу.
- **Управление** (администратор) — участники с достигнутым порогом роли, отчёты, CSV, отмена последней записи. Технические действия вынесены в **Сервис**.

В карточке участника администратор добавляет плейсмент или заметку по шагам: тип → текст → проверка → подтверждение. Перед сохранением текст можно исправить. Выдача роли и отмена записи также требуют подтверждения. Повторное нажатие «Сохранить» не добавляет вторую запись. `/cancel` и кнопка отмены завершают ввод; незавершённая форма истекает через 15 минут. После перезапуска незавершённый ввод нужно начать заново.

В списке плейсментов или заметок открой нужную запись: можно исправить текст, сменить Small / Big или удалить запись. Все изменения требуют подтверждения и сохраняются в **Истории изменений** с автором, датой и предыдущим содержанием. Удалённую запись можно восстановить однократно, с исходной датой. Записи, уже вошедшие в подтверждённый цикл роли, защищены от изменения, удаления и восстановления. Устаревший экран не перезаписывает более новое исправление другого администратора.

В разделе **Отчёты** можно просмотреть прошлую календарную неделю и выключить автоотчёт после подтверждения. Выбор группы / топика: ответь `/setreport` на сообщение в нужном топике. Отчёт отправляется по понедельникам в 12:00 по часовому поясу бота.

В меню команд 4 пункта для участников и 6 для администраторов. Старые команды чтения открывают соответствующий кнопочный экран. Старые `/place`, `/note`, `/role`, `/undo`, `/snapshot` открывают карточку или управление: **они больше не изменяют данные сразу**. Для записи используй кнопки и подтверждение. `/stats` и `/profile` без аргументов показывают собственную карточку.

Навигация меняет одно сообщение. Запрос из группы открывает карточку в личке; чтобы бот мог написать, сначала нажми Start. Кнопки привязаны к пользователю, открывшему карточку. Чужие профили, заметки, рейтинг и администрирование доступны только ID из `ADMIN_IDS`.

Периоды расположены по два в ряд. В рейтинге нажми «Категория», чтобы выбрать показатель. Внизу экрана — одна строка перехода назад и в главное меню. Превью записей сокращены; полный текст доступен через «Открыть». Ссылки на пустые заметки, сообщения и историю правок скрыты в профиле.

## Как считается активность

- Аудио и музыкальные документы (`.wav`, `.mp3`, `.mid` и т. д.) — лупы.
- ZIP / RAR / 7Z и другие архивы — архивы.
- Фото, видео, GIF и видеокружки — медиа.
- Текст и голосовые — сообщения. Другие документы — файлы.
- `#opportunity` — дополнительный признак, не отдельное действие; похожие теги вроде `#opportunity_extra` не считаются.

Команды, сообщения ботов, служебные события и другие чаты не учитываются. Для задержанных обновлений используется исходная дата Telegram. Повторная доставка одного сообщения не увеличивает счётчик. Дни и текущая серия считаются в `BOT_TIMEZONE`; статистика ограничена `TRACK_CHAT_ID`.

Telegram не передаёт всю старую переписку: бот считает полученные обновления. Изменения классификации действуют для новых сообщений; старые записи автоматически не переименовываются. Роли в Telegram выдаются вручную, кнопка подтверждения сохраняет историю и начинает новый цикл соответствующей шкалы.

## Требования

- Python 3.11 или новее
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather)
- ID администраторов и отслеживаемого чата

## Установка

```bash
git clone https://github.com/sixsensegoeshard/sixsense-stash.git
cd sixsense-stash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

На Windows активация окружения выглядит так:

```powershell
.venv\Scripts\Activate.ps1
```

## Настройка `.env`

Открой `.env` и заполни:

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота от BotFather |
| `ADMIN_IDS` | ID администраторов через запятую |
| `TRACK_CHAT_ID` | ID группы или супергруппы для отслеживания |
| `DB_URL` | URL базы данных; по умолчанию SQLite-файл `tracker_v3.db` |
| `BOT_TIMEZONE` | Часовой пояс для отчётов, например `Europe/Moscow` |
| `REQUIRE_TRACK_CHAT_ID` | `1` — требовать чат, `0` — разрешить запуск без него |

Дополнительные пороги статистики находятся в `.env.example`.

## Настройка Telegram

1. Создай бота через BotFather и скопируй токен в `BOT_TOKEN`.
2. Добавь бота в нужную группу.
3. Выдай ему права администратора, если боту нужно видеть обычные сообщения.
4. Узнай числовой ID группы и укажи его в `TRACK_CHAT_ID`.
5. Узнай свой Telegram ID и укажи его в `ADMIN_IDS`.

Не публикуй `.env`: в нём находится секретный токен бота. Этот файл уже добавлен в `.gitignore`.

## Запуск

```bash
source .venv/bin/activate
python trackerbot.py
```

Остановка — `Ctrl+C`.

После обновления кода останови старый процесс и запусти бота заново — только так он загрузит изменения и обновит меню команд Telegram. Одновременно должен работать один экземпляр с этим токеном.

## Проверки

```bash
python -m unittest discover -s tests -v
python -m py_compile trackerbot.py tracker_ui.py tracker_insights.py tracker_records.py
python -m pip check
```

Тесты используют искусственные Telegram-обновления, подмену API и SQLite в памяти. Они не читают рабочий `.env`, не подключаются к Telegram и не меняют реальную базу.

## Структура

- `trackerbot.py` — исходный код бота.
- `tracker_ui.py` — экраны, кнопки и пошаговый ввод.
- `tracker_records.py` — проверка исправлений, история изменений и восстановление записей.
- `tracker_insights.py` — поиск, сортировка, месяцы и сравнение периодов.
- `tests/` — проверки учёта, поиска, доступа и навигации.
- `.env.example` — пример настроек без секретов.
- `requirements.txt` — зависимости Python.
- Файл из `DB_URL` — локальная база; существующий путь из `.env` сохраняется.
- `backups/` — локальные резервные копии, не загружаются на GitHub.

## Сохранённая стабильная версия

Перед обновлением 1 ноября сохранена версия `33eaaea`: Git-метка `stable-2026-11-01-33eaaea` и локальная папка `backups/checkpoints/2026-11-01_02-52-25-33eaaea/`. В папке — исходники, согласованная SQLite-копия, локальная конфигурация и контрольные суммы. Конфигурация и база не загружаются на GitHub.

Создание следующего полного сейва:

```bash
.venv/bin/python tools/checkpoint.py create --database tracker_v4.db
```

Проверка сохранённого сейва:

```bash
.venv/bin/python tools/checkpoint.py verify backups/checkpoints/2026-11-01_02-52-25-33eaaea
```

Восстановление кода, настроек и базы **в новую папку**, без замены работающей установки:

```bash
.venv/bin/python tools/checkpoint.py restore backups/checkpoints/2026-11-01_02-52-25-33eaaea ../tg-bot-restored
```

Затем установи зависимости в восстановленной папке по инструкции запуска. Перед переключением останови текущий экземпляр и сохрани свежую базу. Копия возвращает данные на момент сейва; записи после сейва в ней отсутствуют. Одновременно должен работать один экземпляр с твоим токеном.

Старый сейв `stable-2026-10-12` (`6b58c82`) также сохранён.

Для просмотра старой версии в отдельной папке:

```bash
git worktree add --detach ../tg-bot-stable stable-2026-11-01-33eaaea
```

Обновление не меняет схему базы; добавлены служебные отметки безопасной очистки. Очистка удерживает текущий месяц и полную прошлую неделю для отчётов. Если исходные сообщения архивного месяца уже удалены, пересчёт отказывается заменять сохранённые итоги неполными данными.
